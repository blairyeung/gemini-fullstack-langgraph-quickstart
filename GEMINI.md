# Gemini Fullstack LangGraph Quickstart

This document provides a technical overview of the Gemini Fullstack LangGraph Quickstart project, including its architecture, agent design, tools, and workflows.

## Project Structure

The project is a monorepo with two main components:

-   `frontend/`: A React-based user interface built with Vite, TypeScript, and Tailwind CSS.
-   `backend/`: A Python-based backend powered by LangGraph and FastAPI, which hosts the research agent.

### Key Files and Directories

-   `frontend/src/App.tsx`: The main React component that manages the application state and user interactions.
-   `backend/src/agent/graph.py`: Defines the LangGraph agent, including its nodes, edges, and overall workflow.
-   `backend/src/agent/prompts.py`: Contains the prompts that guide the agent's behavior at each step of the research process.
-   `backend/src/agent/state.py`: Defines the state objects used by the LangGraph agent.
-   `backend/src/agent/tools_and_schemas.py`: Contains the Pydantic schemas for data validation and the tools used by the agent.
-   `docker-compose.yml`: Configures the services for production deployment, including the backend, Redis, and Postgres.
-   `Makefile`: Provides convenience commands for development, such as starting the frontend and backend servers.

## Agent Architecture

The core of this project is the LangGraph-powered research agent. The agent is designed to conduct comprehensive research on a given topic by iteratively searching the web, reflecting on the results, and refining its search until it has enough information to provide a well-supported answer.

### Agent State

The agent's state is managed by the `OverallState` TypedDict, which includes the following key fields:

-   `messages`: A list of messages in the conversation.
-   `search_query`: The current search query.
-   `web_research_result`: The results of the web search.
-   `sources_gathered`: A list of URLs for the sources found during research.
-   `research_loop_count`: The number of research iterations.

### Agent Workflow

The agent's workflow is defined as a state graph in `backend/src/agent/graph.py`. The graph consists of the following nodes:

1.  **`generate_query`**: Generates initial search queries based on the user's input. This node uses the `query_writer_instructions` prompt to generate a `SearchQueryList`.
2.  **`web_research`**: Performs a web search using the DuckDuckGo Search API. This node uses the `web_searcher_instructions` prompt to summarize the search results.
3.  **`reflection`**: Analyzes the search results to identify knowledge gaps and generate follow-up queries. This node uses the `reflection_instructions` prompt to generate a `Reflection` object.
4.  **`finalize_answer`**: Synthesizes the gathered information into a final answer with citations. This node uses the `answer_instructions` prompt to generate the final response.

The agent transitions between these states based on the conditions defined in the graph, such as whether the research is sufficient or if the maximum number of iterations has been reached.

### Detailed Graph Analysis: `backend/src/agent/graph.py`

The `graph.py` file is the heart of the agent, defining its structure and logic. Here's a breakdown of its key components:

-   **Nodes**: Each function (`generate_query`, `web_research`, `reflection`, `finalize_answer`) represents a node in the graph. These nodes are responsible for a specific task in the research process.
-   **Edges**: The `builder.add_edge()` and `builder.add_conditional_edges()` calls define the connections between the nodes. These edges control the flow of the agent, determining which node is executed next.
-   **State**: The `OverallState` TypedDict is the shared state of the graph. Each node can read from and write to this state, allowing them to share information and collaborate on the research task.
-   **Configuration**: The `Configuration` class allows you to customize the agent's behavior, such as the language models to use and the number of research loops to perform.
-   **Prompts**: The prompts in `backend/src/agent/prompts.py` are crucial for guiding the agent's behavior. Each prompt is carefully crafted to instruct the language model on how to perform its task, such as generating search queries or reflecting on the research results.

## Tools and Schemas

The agent uses the following tools and schemas:

-   **`SearchQueryList`**: A Pydantic schema for validating the list of search queries generated by the agent.
-   **`Reflection`**: A Pydantic schema for validating the reflection process, including whether the research is sufficient and any identified knowledge gaps.
-   **DuckDuckGo Search API**: The tool used for performing web searches.

## Technical Details

-   **Backend Framework**: FastAPI
-   **Agent Framework**: LangGraph
-   **LLM**: Google Gemini
-   **Frontend Framework**: React (with Vite)
-   **Styling**: Tailwind CSS and Shadcn UI
-   **Deployment**: Docker

## Workflows

### Development

1.  Install dependencies for both the frontend and backend.
2.  Set up the `.env` file with your Gemini API key.
3.  Run `make dev` to start the development servers for both the frontend and backend.

### Production

1.  Build the Docker image using the provided `Dockerfile`.
2.  Run `docker-compose up` to start the production services, including the backend, Redis, and Postgres.
